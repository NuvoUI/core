# AGENTS.md

Guidance for AI coding tools working on this repository (`@nuvoui/core`, version 2.0.0).

## 1. What this repo is

NuvoUI core is a human-readable, utility-first SCSS framework and the foundation layer of a design system: design tokens as `--nu-*` custom properties, utility classes, and SCSS mixins.
It ships SCSS and compiled CSS only. No JavaScript is shipped; the `.mjs` files here are tests and generators.

## 2. Commands

Run from the repository root. `pnpm` and `npm` both work (`pnpm-lock.yaml` is committed).

| Command | What it does |
| --- | --- |
| `pnpm test` | Runs contrast, tokens, mixins, config, docblocks, mixins-map sync, scales check, size and TOKENS.md check |
| `pnpm test:perf` | `apply()` compile-time guard against v1 (extracts the 1.5.7 sources from git; skipped without git history) |
| `pnpm test:all` | `test` then `test:perf` |
| `pnpm lint` | stylelint on `src/**/*.scss` |
| `pnpm format` / `pnpm format:check` | Prettier write / check on `src`, `test/[a-z]*.mjs`, `scripts/**/*.mjs` |
| `pnpm docs:tokens` | Regenerates `docs/TOKENS.md` |
| `pnpm scales` | Regenerates `src/styles/functions/_default-scales.scss` |
| `pnpm build` | Cleans `dist/`, compiles `src/styles/build.scss` to `dist/nuvoui.css` and `dist/nuvoui.min.css` |
| `pnpm dev` | Watches `src/styles/index.scss` into `dist/nuvoui.css` |

`prepublishOnly` runs lint, `test:all`, `format:check` and build. Before finishing a change, run at least `pnpm test`, `pnpm lint` and `pnpm format:check`.

## 3. Repository layout

```
src/styles/
  index.scss        Public entry (@use "@nuvoui/core"): forwards config, functions, utilities, layouts, tools
  build.scss        Prebuilt entry with every utility class (feeds dist/ and the size/token tests)
  mixins-map.scss   Generated. apply() registry (@use "mixins-map" as *)
  mixins-map.json   Generated. Same data as JSON
  config/           Configuration variables and maps ($brand, $spacers, $breakpoints, feature flags, theme validation)
  functions/        Colour parsing, OKLCH scale generation, token(), units, math, feature flags, _default-scales.scss (generated)
  themes/           Token emission: light, dark, inverse, high-contrast
  utilities/        Utility classes and their mixins, one file per property family
  layouts/          flex, grid, container
  tools/            Media queries, container queries, accessibility, feature support, modern layout
  base/             Reset and base element styles
  components/       Tooltips
test/               *.mjs suites (contrast, tokens, mixins, config, docblocks, mixins-map-sync, size, perf), helpers.mjs, fixtures/
scripts/            generate-scales.mjs, token-reference.mjs
docs/               TOKENS.md (generated), MIGRATION-v2.md, DOC-BLOCKS.md
```

Also: `CHANGELOG.md`, `README.md`, `dist/` (build output).

## 4. Engineering rules for changes

- No silent fallbacks. Invalid input raises a compile error that names the fix (the unknown key, the close matches, the accepted values). Never coerce or ignore bad input.
- The three `apply()` paths must behave the same for every change:
  1. `@use "index" as *;` with `@include apply(...)`
  2. `@use "mixins-map" as *;` with `@include apply(...)`
  3. Namespaced, `@use "index" as NuvoUI;` with `@include NuvoUI.apply(...)`
- `mixins-map.scss` and `mixins-map.json` are generated by a separate tools repository (`tools/build.js`, not in this repo). Do not hand-edit them. When a mixin is added, renamed or removed, the generated files must be regenerated and stay in sync; `test/mixins-map-sync.mjs` enforces it (it is skipped with a notice when the tools checkout is absent, so do not treat a skip as a pass).
- Every public mixin and function carries a doc block above it, in the format defined in `docs/DOC-BLOCKS.md`. `test/docblocks.mjs` validates every block and compiles every `@example`. Use `//` comments only, never `/* */`.
- Keep code comments short. Do not narrate history or decisions in source.
- After any token change (names, default values, themes, scales), run `pnpm docs:tokens`. Never hand-edit `docs/TOKENS.md`. After changing default colours or the shade generator, run `pnpm scales`. Never hand-edit `functions/_default-scales.scss`.
- Behaviour changes need an entry in `CHANGELOG.md` and, for anything a 1.x user would notice, an update to `docs/MIGRATION-v2.md`.
- Add tests that fail without the change. Put them in the suite that owns the area (`test/mixins.mjs`, `test/tokens.mjs`, `test/config.mjs`, and so on).
- The performance guard (`pnpm test:perf`) and the size guard (`test/size.mjs`) must stay within their limits. Update the size baselines only for an intended size change, with the reason in the change description.
- Dart Sass is a peer dependency, range `>=1.79.0 <2` (see `package.json`). Use module syntax (`@use`, `sass:map`, `sass:list`) and no deprecated global built-ins such as `map-get`.
- Keep the change small and in the narrowest code path. Do not refactor adjacent code.

## 5. Writing NuvoUI code

Full usage guide: https://nuvoui.io/llms-full.txt. Documentation: https://nuvoui.io/core/.

- Modifiers come after the utility inside `apply()`: state first, then breakpoint.
  ```scss
  @use "@nuvoui/core" as *;

  .card {
      @include apply(bg(gray, 100) hover lg, p(4), bg(brand));
  }
  ```
  Not `hover:bg(gray, 100)` and not `lg:hover:bg(gray, 100)`.
- Class names use the breakpoint as an `@` suffix and the state as a prefix: `p-4@lg`, `hover:text-white`, `group-hover:...`. Not every class has every variant (colour classes such as `bg-brand` have no responsive form); check the compiled output before relying on one. For a responsive colour use the mixin: `apply(bg(red) lg)`.
- Flex modifiers (`between`, `x-center`, `row`, `col`, `wrap`) go on the same element as `.flex`. Flex child classes (`fill-*`, `grow`, `self-*`, `order-*`) only work on direct children of a `.flex` parent.
- Names are readable words: `between`, `x-center`, `x-start`, not abbreviations of CSS property values.
- A unitless number is a configuration key, not a raw value: `p(4)` gives `padding: var(--nu-space-4)`. A number that is not a key raises an error. Values with units pass through: `p(1.5rem)`.
- Colour roles are bare tokens: `--nu-brand`, `bg(brand)`, `.bg-brand`. There is no `-default` suffix. Shades are `brand-100`, `gray-950`.
- Prefer theme tokens and role words (`bg(surface)`, `text-color(muted)`, `token(text-muted)`) over hex values, so themes, dark mode and high contrast keep working.
- Before writing any SCSS example (docs, doc blocks, tests, answers), compile it against `src/styles` in a scratch directory, for example `sass --load-path=src/styles scratch/example.scss`. Every class you reference must exist in a compiled `src/styles/build.scss`; grep the output.
